# BYD Stock Monitor — Multi-Model Dashboard with Colour Tracking

- **Date:** 2026-09-02
- **Status:** Approved design

## Context

`monitor.py` currently fetches the BYD Dealer Group inventory page
(`https://evdealergroup-byd.com.au/inventory?type=d`), parses vehicle cards,
logs only **Atto 2** units by (state, variant) into `history.csv`, and emails
when new Atto 2 Dynamic units appear. `graph.py` reads that CSV and renders a
single Plotly line chart (one line per "State Variant") into `index.html`,
served on GitHub Pages.

The page actually contains **12 distinct models** (Atto 1/2/3, Seal, Seal 6,
Seal 6 Touring, Sealion 5/6/7/8, Shark 6, Dolphin) across ~1,750 cards. Each
card's class tokens also encode its **colour** (a curated BYD palette, e.g.
`do-thaumasblack`) alongside model, variant, and state tokens.

The user wants:
1. **Real multi-model tracking** — all models logged, not just Atto 2.
2. **Colour tracking** — counts per (state, model, variant, colour) cell.
3. A **model-spotlight dashboard**: pick a model, see its colour breakdown,
   variant time-series, and per-state counts.
4. A **comfortable modern UI** using Tailwind + Alpine.js (via CDN).

User-confirmed decisions:
- **Primary view:** Model spotlight — pick a model, see colour breakdown bar
  chart + counts, plus its time-series.
- **Granularity:** one history row per (state, model, variant, colour) cell
  present per poll.
- **Notifications:** unchanged — email remains Atto 2 Dynamic only. Multi-model
  tracking is for the dashboard, not alerts.
- **UI:** Tailwind + Alpine.js via CDN, still generated by the stdlib Python
  script (no build step).
- **Legacy history:** start fresh. Existing Atto-2-only `history.csv` is
  archived to `history-legacy.csv`; the new schema starts clean.

## Design

### 1. History schema (`history.csv`)

New header, one row per present (state, model, variant, colour) cell:

```
timestamp_utc,state,model,variant,colour,count,stock_numbers
```

- `timestamp_utc` — `YYYY-MM-DD HH:MM:SS UTC`.
- `state` — `WA`, `VIC`, `NSW`, `QLD`, `SA`, `ACT`, `NT`, `TAS`.
- `model` — canonical display name, e.g. `Atto 2`, `Sealion 8`.
- `variant` — variant label, e.g. `Dynamic`, `Premium`, `Demo`, or `Unknown`.
- `colour` — canonical display name from the colour token map (e.g. `Thaumas
  Black`), or `Unknown` when no colour token (or an unknown token) is present.
- `count` — number of units in that cell at that poll.
- `stock_numbers` — semicolon-separated stock numbers of the units in that
  cell; empty when count is 0.

Rows are **appended** each run. The old file is renamed to `history-legacy.csv`
once (committed for posterity); a fresh `history.csv` with the new header is
created on first run of the new code.

### 2. Model and colour catalogs (`monitor.py`)

Two curated constant maps translate card class tokens to display names.

**`MODELS`** — 12 entries, token → e.g.:
`do-atto-1` → `Atto 1`, `do-atto-2` → `Atto 2`, `do-atto-3` → `Atto 3`,
`do-seal` → `Seal`, `do-seal-6` → `Seal 6`, `do-seal-6-touring` → `Seal 6
Touring`, `do-sealion-5` → `Sealion 5`, `do-sealion-6` → `Sealion 6`,
`do-sealion-7` → `Sealion 7`, `do-sealion-8` → `Sealion 8`, `do-shark-6` →
`Shark 6`, `do-dolphin` → `Dolphin`.

**`COLOURS`** — curated palette of ~24 paint names, token → display name, e.g.:
`do-thaumasblack` → `Thaumas Black`, `do-aurorawhite` → `Aurora White`,
`do-15steel` is **not** a colour (it is a wheel token) and must not appear in
this map; a static unit test enumerates the live token set and asserts every
`do-*` token on the page resolves to exactly one of: model, variant, state,
colour, wheel, or status (the "known token" invariant).

`parse_cards` gains `model` and `colour` fields on each card, derived by
matched tokens (first matching model token / colour token in the card's class
list). Cards with no colour token get `colour = "Unknown"`.

### 3. Counting and history writing (`monitor.py`)

- `collect_counts(cards)` replaces the Atto-2-specific `count_by_state`. It
  aggregates all validated cards — status in {available, in-transit} with a
  stock number, any model — into a nested structure keyed by
  (state, model, variant, colour), including per-cell stock-number sets.
- `append_history` writes one row per present cell, sorted deterministically.
- `variant_of` and demo detection are unchanged. `is_target`, `is_atto2`,
  `send_email`, `log_matches`, `load_state`/`save_state` are unchanged —
  notification behaviour is preserved exactly.
- The Atto-2-only console table (`print_state_table`) becomes a per-model total
  summary (total units per model, grand total) plus, optionally, per-state
  counts for the requested spotlight model.

### 4. Dashboard generation (`graph.py`)

Still stdlib-only Python emitting a self-contained `index.html`. Data is
embedded as a JSON object (`const MODELS = {...}`) and rendered with:
- **Tailwind CSS** (CDN) for layout/components.
- **Alpine.js** (CDN) for selector state.
- **Plotly** (CDN) for the two charts.

The dashboard's model-spotlight layout:
- A **chip bar** of all 12 models (Alpine-bound); clicking a chip selects it.
- A **colour breakdown** — Plotly bar chart of current counts per colour for
  the selected model, plus a colour count table/pills next to it.
- A **variant time-series** — Plotly line chart, one line per variant of the
  selected model over time (legend click toggles).
- A **per-state counts** block for the selected model.

`graph.py` reads the new schema (loader rejects/returns-empty on the old
header), and renders an **empty state** cleanly when `history.csv` is missing,
empty, or lacks rows for a model.

### 5. Files changed

- `monitor.py` — catalogs, parse fields, collect/append, console summary.
- `graph.py` — new loader, snapshot builder, timeseries builder, new renderer.
- `tests/test_history.py` — updated lifecycle tests for new schema + mappings.
- `tests/test_graph.py` — new-schema loader/snapshot/timeseries/render tests.
- `history.csv` → archived to `history-legacy.csv`; fresh `history.csv`.
- `.github/workflows/monitor.yml` — unchanged (still commits
  `history.csv state.json notifications.log index.html`).
- `README.md` — reflect multi-model + colour tracking and the dashboard.

### 6. Testing

- Unit tests for `MODELS`/`COLOURS` mapping; unknown/unmatched tokens → fall
  back to `Unknown`.
- Static test: live token set invariant (every `do-*` token on the fetched page
  resolves into a known category).
- `append_history` writes one row per (state, model, variant, colour) cell,
  ascending and deduplicated, with per-cell stock numbers.
- Loader handles empty/missing file and old-schema header without crashing.
- Snapshot builder separates the latest timestamp's colour counts; timeseries
  builder groups per (model, variant) with real dates.
- Render contains Tailwind, Alpine, and Plotly script tags and `const MODELS`
  data matching the loader output; empty state renders.
- `uv run pytest` all green.
